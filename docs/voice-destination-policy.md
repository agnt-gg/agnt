# Native voice pre-execution destination policy

Native receipt requests (X-AGNT-Voice-Request-Id or voiceMetadata) now require an authenticated AGNT user, valid fresh-request identifier shape, and explicit provider/model. `routingMode` must be absent or `pinned`. Unknown/default/dynamic resolution is rejected before settings, global default writes, routing probes, inference, or tool execution. Native voice never builds configured fallback chains. Every inference tier is checked against the exact selected provider/model before dispatch. Ordinary text retains its routing/fallback behavior. Legacy `voiceMode` alone remains an answer-register hint, not native receipt authorization.

The pin constrains the provider key (including the distinction between openai-codex and openai-codex-2) and model; it does **not** attest the underlying provider account or entitlement. Unsupported body-level account claims are rejected. Existing server-owned provider authentication remains responsible for credential selection; no new credential storage or account inference was introduced. Supported-account live qualification and account mutation during a run remain unverified. Request nonce shape validation is not authentication or a durable anti-replay ledger.

Verification: actual production handler imported under Vitest with isolated data and mocked settings/routing/client/tools. Ten previously failing cases now pass plus the ordinary-text control. Missing message intentionally terminates chain-construction probes before SSE; these tests are not paid inference, authenticated HTTP or live completion tests. Direct policy tests cover provider/account-key/model drift, JSON/multipart missing nonce, and legacy compatibility. Frozen independent audits and existing routing assertions are unchanged.

Remaining release gates include authenticated HTTP persistence/recovery races, supported account attestation, full UI/build repairs, valid selected-model rendered dogfood with downstream PCM/ASR evidence, owner-admitted faster-Qwen streaming qualification and human acoustic acceptance (PENDING_USER). No claim of mission completion.
